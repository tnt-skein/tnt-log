# Журнал: фасад над встроенным `log`

`tnt-log` пишет записи во встроенный журнал Tarantool — `log.new(имя
модуля)`, вид json или plain, уровни по модулям — и закрывает то, чего
ядро не делает: прячет тайны до передачи ядру, обезвреживает значения,
на которых ядро бросает или портит запись, держит потолок записи ниже
буфера ядра, подставляет поля в сообщение по имени и подавляет подряд
идущие повторы.

```lua
local log = require('tnt.log')

local pool = log.new('tnt.pool')

pool.warn('соединение {endpoint} не открылось, попытка {attempt}', { endpoint = uri, attempt = 3 })
-- message: "соединение postgres://root:[скрыто]@db не открылось, попытка 3"
-- fields:  { endpoint = "postgres://root:[скрыто]@db", attempt = 3 }
```

Писать записи, держать файл, переоткрывать его по SIGHUP, фильтровать по
уровню и печатать JSON умеет само ядро; своего писателя у пакета нет.
Уровень, вид, назначение и нарезка принадлежат ядру и разделу `log`
конфигурации кластера — настроек у пакета нет.

Зависит от `tnt-context` (поля контекста файбера в каждой записи)
и `tnt-external` (подмена журнала ядра в проверках).

## Зачем пакет

Фасад закрывает то, чего ядро не делает и что стоит дорого, если забыть.
Каждая строка таблицы проверена прогоном против голого `require('log')`
на Tarantool 3.8.0:

| Беда встроенного журнала | Что делает фасад |
|---|---|
| пароль из поля и из `log.info('%s', tbl)` печатается как есть | прячет тайны **до** передачи ядру |
| `log.info('%s %d', 'a', 1)` кладёт `a` в поле, а `1` молча выбрасывает | всё после `fields` — в `args` |
| `nan`/`inf` пишутся литералами; строгий разборщик (`json.loads` Python, `json.new()` с `decode_invalid_numbers = false`) падает, `json.decode` ядра их читает | пишет их строками `"nan"`, `"inf"`, `"-inf"` |
| int64 пишется голым числом, разборщик на double теряет цифры | за пределами ±2^53 — десятичной строкой |
| невалидный UTF-8 проходит сырыми байтами | `[не UTF-8, N байт]` |
| кольцо и 129-я вложенная таблица бросают в вызывающего `Too high nest level` (128 проходят), ключ-boolean — `table key must be a number or string` | `[кольцо]`, `[глубже]`, ключ строкой |
| запись длиннее ~16 КБ режется: сообщение-строка — внутри кавычек, кавычка закрыта, NUL нет; таблица-запись — с NUL внутри и битым JSON; в plain обрезанная запись склеивается со следующей без перевода строки | потолок строки 4096 байт и записи 15000 байт |
| поля `time` и `module` вызывающего дублируются рядом с полями ядра, а `file`, `level`, `pid`, `line`, `cord_name`, `fiber_name`, `fiber_id`, `error_msg` молча выбрасываются | всё переданное лежит внутри `fields` |
| таблица с `__tostring` без своих ключей превращается в `[]`, а с ключами `__tostring` игнорируется и содержимое печатается как есть — то, что он должен был скрыть; `{msg=…}` даёт запись без `message` | `__tostring` соблюдается всегда, `message` есть всегда |
| бросающий `__serialize` бросает в вызывающего; функцию, `'map'` и `'seq'` ядро соблюдает само | `[__serialize бросил]` вместо ошибки |

Сверх таблицы фасад делает три вещи, которых у ядра нет вовсе:

- **Подставляет поля в сообщение по имени.** `{endpoint}` в тексте
  становится значением поля — уже очищенным, — а само поле остаётся
  в `fields`, по нему ищут в сборщике.
- **Кладёт в запись контекст файбера.** Опознаватели запроса и трассы
  из `tnt-context` — верхними полями, прочие ключи — объектом `context`;
  так запись находится по запросу, из которого её написали.
- **Подавляет подряд идущие повторы.** Циклический агент рассказывает
  о своей беде каждый такт, и за минуту молчащего хранилища в журнале
  набралось бы шестьдесят одинаковых строк; `changes` пишет первую,
  а к записи, которая наконец изменилась, добавляет `suppressed` —
  сколько раз повторилась прежняя.

И правило тайн (`secret`, `scrub`) отдаётся наружу: тот, кто показывает
причину отказа человеку, прячет тайны тем же правилом, а не своей копией.

## Как пользоваться

```lua
local log = require('tnt.log')

local pool = log.new('tnt.pool')          -- журнал модуля: debug, info, warn, error
local agent = log.changes('tnt.failover') -- то же, но подряд идущие повторы подавляются

pool.warn('соединение {endpoint} не открылось, попытка {attempt}', { endpoint = uri, attempt = 3 })
-- message: "соединение postgres://root:[скрыто]@db не открылось, попытка 3"
-- fields:  { endpoint = "postgres://root:[скрыто]@db", attempt = 3 }
pool.info('пул готов')
```

- Метод ничего не возвращает и **никогда не бросает**: запись о беде не должна
  становиться второй бедой.
- `msg` — строка. Таблица уходит строкой JSON своей очищенной копии, прочее —
  строкой по правилам раздела «Значения»: `42` → `"42"`, `nil` → `[nil]`,
  функция → `[function]`.
- `{имя}` в строке — заполнитель, как в договоре журнала PSR-3: на его
  место встаёт значение поля из **уже очищенных**
  `fields`, а само поле остаётся в `fields` — по нему ищут в сборщике.
  Правила — в разделе «Заполнители».
- `fields` — таблица или nil. Иное непустое значение уходит в `fields.value`.
- Всё, что передано после `fields`, попадает в `args` — массив очищенных
  значений: `pool.info('%s %d', 'a', 1)` даёт `fields = { value = 'a' }`
  и `args = { 1 }`. Ничего не теряется.
- Имя журнала — слово до 128 байт из латиницы, цифр, точки, подчёркивания
  и дефиса, иначе `new`/`changes` сразу бросают: это ошибка сборки. Имя
  дословно уходит ядру и в поле `module`, а ядро пишет его в заголовок
  каждой записи мимо фасада: длинное имя пробило бы потолок записи, кавычка
  и перевод строки ломали бы plain, невалидный UTF-8 — строгий JSON.

Остальное наружу:

| Что | Зачем |
|---|---|
| `log.secret_hints` | подстроки имён, под которыми лежит тайна; читается на каждой записи |
| `log.secret(name)` | похоже ли имя на тайну |
| `log.scrub(text)` | строка со спрятанными тайнами, не длиннее окна в 8192 байта и `…`; не строка возвращается как есть |
| `log.is_name(name)`, `log.NAME_RULE` | годится ли значение в имя журнала и правило словами — для тех, кто принимает имя журнала в своей настройке, например меткой слоя конвейера |
| `log.render(record)` | тело записи в виде plain |
| `log.HIDDEN`, `log.CYCLE` | `[скрыто]` и `[кольцо]` |
| `log._set_source(подмена)` | внешние зависимости `tnt.external`: журнал ядра (`logger`), его настройка (`settings`), имя инстанса (`instance_name`), поля контекста (`context`) — только для проверок |

```lua
log.secret('X-Api-Key')                      --> true
log.scrub('postgres://root:hunter2@db')      --> 'postgres://root:[скрыто]@db'
log.is_name('tnt.pool'), log.is_name('пул')  --> true, false
log.render({ message = 'пул готов', fields = { attempt = 3 } })
--> 'пул готов attempt=3'
```

## Запись

Выдержка из одного прогона: `box.cfg{ instance_name = 'router-001-a',
log_format = 'json' }`, потом `pool.warn` с паролем в поле и в адресе,
`pool.info` без полей и три одинаковых записи `changes` перед четвёртой.
Первая запись серии пишется, две следующие подавлены, последняя несёт
`suppressed = 2`; строки ядра до и после записей фасада опущены.

### Поля

| Поле | Чьё | Что |
|---|---|---|
| `time`, `level`, `pid`, `cord_name`, `fiber_id`, `fiber_name`, `file`, `line`, `module` | ядро | фасад их не пишет и не дублирует |
| `message` | фасад | всегда строка, тайны спрятаны, не длиннее 4096 байт плюс «…» |
| `fields` | фасад | только если после очистки не пусто; ключи верхнего уровня — строки |
| `args` | фасад | массив очищенных значений, переданных после `fields`; только если передано хоть что-то; `nil` внутри — строкой `[nil]`, чтобы позиции не сдвигались |
| `instance_name` | фасад | `box.cfg.instance_name`; только в json и только после `box.cfg` |
| `request_id` | контекст файбера | опознаватель запроса; в области, открытой с `request_id` |
| `trace_id`, `span_id`, `trace_flags` | контекст файбера | опознаватели трассы; в трассе — ключи объявляет тот, кто её ведёт, фасад берёт их готовыми |
| `context` | контекст файбера | объект: прочие ключи контекста с `log = true`; только если такие есть |
| `suppressed` | фасад | целое ≥ 1; только у записи `changes`, прервавшей серию |
| `truncated` | фасад | `true`; только когда что-то урезано или поля отброшены |

Всё переданное вызывающим лежит внутри `fields` под любыми именами — `time`,
`level`, `message`, `module`, `instance_name`, `request_id`, `suppressed`,
`args` и прочими. Ни одно не теряется, не дублирует поле ядра и не подменяет
поле фасада. Списка «занятых» имён в фасаде нет — поэтому и лишние аргументы
лежат полем уровня записи, а не внутри `fields`. Порядок ключей договором
не является.

Поля контекста фасад берёт из `tnt-context` (`context.log_fields()`, см.
его документ) на каждой записи и кладёт верхними полями — так велит
приложение OpenTelemetry о следах трассы в журналах не-OTLP, и так их ищут
сборщики; прочие ключи лежат объектом `context`, потому что на верху записи
они столкнулись бы с полями фасада и ядра. Значения проходят те же тайны,
обезвреживание и потолки, что `fields`: `request_id`, пришедший из заголовка
клиента, — не своё. Вне области ни одного из пяти полей в записи нет.

```lua
local context = require('tnt.context')

context.declare('user', { log = true })

context.run({ request_id = 'r-7', user = 'ivan' }, function()
    pool.info('в области', { a = 1 })
    -- запись: message = 'в области', fields = { a = 1 },
    --         request_id = 'r-7', context = { user = 'ivan' }
end)

pool.info('вне области', { a = 1 })
-- запись: message = 'вне области', fields = { a = 1 } — ни request_id, ни context
```

`time` — местное время с миллисекундами и смещением без двоеточия
(`+0300`), не строгий RFC 3339; ядро его не настраивает. Python разбирает
его `strptime('%Y-%m-%dT%H:%M:%S.%f%z')` в любой версии, а
`datetime.fromisoformat` — только начиная с 3.11: прежние версии смещения
без двоеточия не принимают.

**Не каждая строка потока — JSON.** Одна-две первые строки ядра на stderr
(`started`, `tcp_server: remove dead UNIX socket`) пишутся до того, как
применён раздел `log`, и остаются plain. Сборщик должен пропускать строки,
которые не разбираются как JSON, либо журнал пишется в файл (`to: file`),
и тогда в нём с первой строки один вид.

### Вид plain

Фасад читает вид из настройки ядра на каждой записи. В plain ядру уходит
строка `render(record)`:

- сначала `message`, управляющие знаки экранированы как в JSON, без кавычек;
- сразу за ним пары фасада: ` suppressed=N`, ` truncated=true`
  и ` args=[…]` — аргументы одним JSON-массивом;
- дальше пары вызывающего ` ключ=значение` по алфавиту. Пары фасада стоят
  раньше нарочно: поле вызывающего по имени `truncated` или `args` иначе
  было бы неотличимо от отметки фасада. В json такой подмены нет — там поля
  вызывающего лежат внутри `fields`;
- последними — поля контекста: ` request_id=…`, ` trace_id=…`, ` span_id=…`
  и ` context.<ключ>=…` по алфавиту ключей. `trace_flags` в plain
  не печатается: человеку он не нужен, а сборщику достаётся json;
- строка берётся в JSON-кавычки, если она пустая или в ней пробельный знак,
  `=`, `"`, `\` или управляющий знак; таблица — JSON, `box.NULL` — `null`,
  число — как в JSON, чтобы большое целое не потеряло цифр;
- `instance_name` не печатается: plain читают на своей машине, а общий поток
  нескольких инстансов пишется в json;
- одна запись — одна строка.

```lua
log.render({
    message = 'назначение\nсменилось',
    suppressed = 2,
    truncated = true,
    args = { 1, 'два' },
    fields = { leader = 'storage-001-b', reason = 'нет связи', truncated = 'своё' },
    request_id = 'r-7',
    trace_flags = '01',
    context = { user = 'ivan' },
})
--> 'назначение\\nсменилось suppressed=2 truncated=true args=[1,"два"] leader=storage-001-b reason="нет связи" truncated=своё request_id=r-7 context.user=ivan'
```

## Значения

| Вход | Выход |
|---|---|
| строка | невалидный UTF-8 → `[не UTF-8, N байт]`; затем тайны; длиннее 4096 байт → обрезка по границе знака, «…» и `truncated` |
| число | `nan`, `inf`, `-inf` → строки; остальные как есть |
| boolean, `box.NULL` | как есть |
| int64/uint64 | в пределах ±2^53 → число, иначе десятичная строка без `LL`/`ULL` |
| прочее cdata (uuid, decimal, datetime, box.error) | `tostring`; бросил или дал не строку → `[cdata]` |
| function / thread | `[function]` / `[thread]` |
| userdata | `__serialize` → его результат по этим же правилам; иначе `tostring`; бросил или дал не строку → `[userdata]` |
| таблица, внутри которой мы уже находимся | `[кольцо]`; вторая ссылка из соседнего поля кольцом не считается |
| таблица с функцией `__serialize` | её результат по этим правилам; бросила → `[__serialize бросил]` |
| таблица с `__tostring` без `__serialize` | `tostring`; бросил или дал не строку → `[__tostring бросил]` |
| глубже 16 уровней | `[глубже]` и `truncated`; переход через `__serialize` считается уровнем, и `__serialize`, отдающий новый объект своего рода, останавливается на том же пределе |
| ключ | строка — UTF-8, тайны и потолок как у значения; целое число в пределах ±2^53 остаётся (массив остаётся массивом), вне их ядро ключом его не принимает — строкой; прочее — `tostring` под `pcall`, бросил или дал не строку → `[table]`, `[cdata]` и так далее по роду; если в таблице есть и строковые, и нестроковые ключи — все ключи строками |

Таблица вызывающего не меняется: строится копия. Ядру уходят только строки,
конечные числа, boolean, `box.NULL` и таблицы из них. Те же правила — для
каждого аргумента в `args`; `nil` среди аргументов — строкой `[nil]`.

```lua
local ring = {}
ring.self = ring

pool.warn('числа и кольцо', { nan = 0 / 0, inf = math.huge, big = 18446744073709551615ULL, ring = ring })
-- fields: { nan = 'nan', inf = 'inf', big = '18446744073709551615', ring = { self = '[кольцо]' } }

pool.warn('байты', { bad = '\xff', [true] = 1 })
-- fields: { bad = '[не UTF-8, 1 байт]', ['true'] = 1 }

pool.info('позиции', nil, 1, nil, 'три')
-- args: { 1, '[nil]', 'три' }
```

**Объект с `__serialize` в полях — полями.** Отказ, у которого есть
`__serialize` с кодом, статусом, опознавателем и причиной, ложится в запись
объектом: по нему отказ ищется кодом и опознавателем, а не строкой цепочки.
Тайны в его полях прячутся тем же правилом, что и везде. Объект, чей
`__serialize` отдаёт строку, ложится этой строкой.

## Заполнители

```lua
pool.warn('соединение {endpoint} не открылось, попытка {attempt}', { endpoint = uri, attempt = 3 })
-- message: "соединение postgres://root:[скрыто]@db не открылось, попытка 3"
-- fields:  { endpoint = "postgres://root:[скрыто]@db", attempt = 3 }
```

- Заполнитель — `{имя}`, имя из `[A-Za-z0-9_.]`, как в PSR-3. Точка — путь
  во вложенную таблицу полей: `{db.host}` — это `fields.db.host`; первый
  сегмент — ключ верхнего уровня `fields`. Сегмент из цифр достаёт и элемент
  массива: `{peers.1}`.
- Значение берётся из **уже очищенных** полей — после вырезания тайн
  и обезвреживания: `{password}` даёт `[скрыто]`, `{obj}` с кольцом — то,
  что лежит в очищенной копии, с `[кольцо]` внутри. Строка подставляется
  как есть; число, boolean и `box.NULL` — как в JSON (`3`, `true`, `null`);
  таблица — JSON своей очищенной копии. Поле остаётся в `fields`.
- Заполнитель, за которым нет поля, с пустым именем, с пустым сегментом
  пути или с недопустимыми знаками остаётся в тексте дословно, как велит
  PSR-3: сообщение с фигурными скобками — обрывок JSON, шаблон — не
  портится. Исключений нет ни при каком входе. `{{a}}` даёт `{значение}`;
  подставленное значение второй раз не разбирается.
- Подстановка идёт после вырезания тайн из самого текста сообщения и до
  обрезки по потолку строки: сообщение может вырасти, и потолок в 4096
  байт с отметкой `truncated` применяется к итогу. Размер записи считается
  по итоговому сообщению.
- Сообщение-таблица заполнителей не знает: оно уходит JSON-ом своей копии.
  Без `fields` заполнители не применяются.
- Цена: образец гоняется только по сообщению с `{` и только при непустых
  полях. Сообщение без скобки — а таких почти все — не платит ничего,
  как строка без `:` и `=` не платит за образцы тайн.

```lua
pool.info('узел {db.host}, первый {peers.1}, пароль {password}, {{a}} и {нет}', {
    db = { host = 'db-1' },
    peers = { 'storage-001-a' },
    password = 'hunter2',
    a = 'значение',
})
-- message: "узел db-1, первый storage-001-a, пароль [скрыто], {значение} и {нет}"
```

## Тайны

По имени: ключ-строка приводится к нижнему регистру, дефис — к
подчёркиванию, и ищется подстрока любого элемента `secret_hints`
(`password`, `passwd`, `secret`, `token`, `cookie`, `authorization`,
`api_key`, `apikey`, `private_key`). Совпало — значение со всем поддеревом
заменяется на `[скрыто]`, на любой глубине, внутри результата `__serialize`
и в таблице-сообщении.

В строке (`scrub`), если имя в паре — тайна:

| Образец | Пример | Итог |
|---|---|---|
| адрес со схемой | `postgres://root:hunter2@db` | `postgres://root:[скрыто]@db` |
| адрес без схемы, как пишут репликация и advertise | `connect to storage:hunter2@10.0.0.5:3301 failed` | `connect to storage:[скрыто]@10.0.0.5:3301 failed` |
| пара через `=` или `:`, с пробелами | `token=abc`, `password = abc`, `X-Api-Key: abc` | `token=[скрыто]` и так далее |
| значение через запятую и скобку | `password=hun,ter2` | `password=[скрыто]` |
| значение в кавычках, и экранированных тоже | `password="два слова"`, `{"password":"hun\"ter2"}`, `{\"token\":\"abc\"}` | `password="[скрыто]"` |
| незакрытая кавычка или закрытая за окном | `password="два слова` | `password="[скрыто]` — до конца строки |
| имя с `authorization` | `Authorization: OAuth abc`, `Authorization:Bot abc` | `Authorization: [скрыто]` — до конца строки текста |
| слово схемы под другим именем | `X-Token: Bearer abc` | `X-Token: [скрыто]` |
| пароль с `@` в паре | `db:password=P@ss` | `db:password=[скрыто]` |
| пара внутри безобидной | `url=https://h/?token=abc`, `error: password=abc` | `url=https://h/?token=[скрыто]` |

Значение пары с безобидным именем не поглощается: следующая пара ищется
сразу за разделителем, и адрес в `url=…` или текст за `error:` проверяются
так же, как вся строка. Имя пары — слово до пробела, `=`, `:`, `&`, `;`,
`?` или кавычки, со скобками, запятой и косой чертой внутри: `secret(1)=…`
и `token/x=…` — такие же тайны, а в `ns:password=…` за безобидной парой `ns:`
находится `password=`. Значение без кавычек идёт
до пробела, `&`, `;` или кавычки. Значение в кавычках закрывает только
кавычка, перед которой чётное число обратных косых (у экранированной —
одна по модулю четырёх): `\"` внутри значения его не кончает.

Под именем с `authorization` значение без кавычек прячется до конца строки
текста вместе со словом схемы: схем много (`OAuth`, `ApiKey`, `Bot`, свои
у каждого сервиса), и список однажды не узнал бы новую. Следующая строка
после `\n` остаётся. Под другими именами за словами схем `Basic`, `Bearer`,
`Digest`, `Negotiate`, `NTLM`, `Token` прячется и сам токен; за словом другой
схемы — только оно само.

Пары прячутся раньше адресов: в `db:password=P@ss` образец адреса без схемы
увидел бы логин `db` и пароль до `@` и, спрятав их первым, съел бы имя
пары, а хвост пароля ушёл бы в запись.

Применяется к `message`, к каждой строке и к каждому ключу на любой
глубине — адрес с паролем в роли ключа такая же утечка. Похоже ли имя поля
на тайну, решается по ключу до обрезки, а ключ-таблица — по тому, что
напечатал её `__tostring`: в записи она выглядит этим именем. Адрес без
схемы узнаётся с начала слова (после пробела, кавычки, скобки, запятой),
но не после косой черты: `узел/записи:7@главная` — путь. Обычный текст
журнала — время `12:30`, IPv6, `user@host`, пути, «ERROR: …» — образцы
не трогают.

Образцы идут за линейное время: 8 КБ злонамеренной строки (`@a:=a:=…`,
`token= aaaa…`, пары подряд) — не больше полутора миллисекунд. Проверки
держат не абсолютный предел, а рост: строка в окно не дороже вчетверо
шестнадцати строк по 512 байт того же вида (у линейного прохода отношение
около единицы, у сломанного под перебор — от шестнадцати). Под хуком
покрытия проход дорожает в десятки раз, и предел в миллисекундах мигал,
а отношение от хука не зависит. Окно в 8192 байта — вторая линия: дальше
образцы не ходят вовсе, и мегабайт стоит столько же, сколько окно. Строка
длиннее окна считается урезанной, даже если после вырезания тайн она
короткая; `scrub` отдаёт её обрезанной по окну с `…` — непроверенный хвост
мог нести тайну.

Правило одно и живёт здесь: тот, кто показывает причину отказа человеку,
берёт `secret` и `scrub` ссылками, а не держит свою копию. Две копии
однажды разъехались — одна не приводила дефис к подчёркиванию, и `X-Api-Key`
в записи был виден.

Список читается на каждой записи: замена целиком, `table.insert` и правка
элемента на месте действуют со следующей записи. Проверенные имена ключей
помнятся (до 1024 имён не длиннее 128 байт, потом память очищается), но
только пока список совпадает со снимком поэлементно. Строки и имена пар
внутри строк сверяются без памяти: память держала бы сами строки, и тысяча
строк вытесняла бы из неё настоящие имена.

```lua
table.insert(log.secret_hints, 'session_id')

pool.info('вход', { session_id = 'abc', ['X-Api-Key'] = 'k', theme = 'dark' })
-- fields: { session_id = '[скрыто]', ['X-Api-Key'] = '[скрыто]', theme = 'dark' }
```

**Ограничения.** Это чёрный список. Тайна под безобидным именем и без образца
(`err = 'пароль hunter2 не подошёл'`) не ловится. `token=expired` в тексте
прячется, хотя тайны в нём нет. Не ловятся закодированный запрос
(`/enter%3Ftoken%3Dabc`) и адрес с `/` внутри пароля; при `@` внутри
пароля прячется только часть до первого `@`, а остаток виден. В паре через `=>`
(`"password"=>"abc"`, вид Ruby) прячется только стрелка, а значение видно.
Не ловится тайна в cookie под именем без подсказки:
в `Cookie: theme=dark; sessionid=abc` прячется `theme=dark` до `;`,
а `sessionid` в списке подсказок нет. Лишнее прячется в
`mailto:ivan@example.org` — по виду это логин с паролем.

## Размер

Буфер записи у ядра ~16 КБ, свой заголовок оно дописывает до ~300 байт.
Поэтому JSON записи, отданной ядру, не длиннее 15000 байт:

- при обходе копится грубая оценка; превысила 15000 — обход прекращается
  (таблица из 60000 ключей не обходится до конца). Поля обходятся раньше
  сообщения: заполнители берут значения из очищенных полей, а сообщение
  идёт в оценку уже с подставленными значениями;
- оценка, умноженная на шесть (управляющий знак в JSON — шесть байт), —
  верхняя граница; если она выше потолка, делается точный замер;
- не влезло или обход прекращён — уходит **запасная запись**: `message`
  с управляющими знаками, заменёнными на `?`, не длиннее 1024 байт плюс «…»,
  `instance_name`, `suppressed`, `truncated = true`; поля и `args`
  отбрасываются;
- правило одно для json и plain: `render` не длиннее JSON той же записи.

Оценка грубая в сторону запаса: запись из тысяч мелких чисел может уйти
запасной раньше, чем её JSON дорастёт до 15000 байт. Поле `suppressed`
добавляется после замера — оно не длиннее тридцати байт, запас буфера ядра
его покрывает. Поля контекста считаются вместе с остальными: запасная
запись сохраняет `request_id`, `trace_id`, `span_id` и `trace_flags`
(они коротки, а запись о том, что не влезло, нужна именно там, где ищут
запрос), но не объект `context`.

```lua
local wide = {}

for index = 1, 60000 do
    wide['k' .. index] = index
end

pool.warn('широкая', wide)
-- запись: { message = 'широкая', truncated = true } — полей нет

pool.warn(string.rep('я', 5000), { blob = string.rep('я', 512 * 1024) })
-- message — 4096 байт «я» и «…»; fields.blob — 4096 байт «я» и «…»; truncated = true
```

## Кто решает уровень

**Только встроенный журнал.** Источники:

- раздел `log` конфигурации кластера: `level`, `modules`, `format`;
- без кластерной конфигурации — `box.cfg{ log_level, log_modules }` или
  `log.cfg{ level, modules }` в стартовом скрипте, либо переменные ядра
  `TT_LOG_LEVEL`, `TT_LOG_FORMAT`, `TT_LOG_MODULES`, `TT_LOG` (действуют при
  первом `box.cfg`/`log.cfg`).

**Переменные и конфигурация кластера.** Под `--config` заданная `TT_LOG_*`
сильнее раздела `log` в `config.yaml` и закрепляет свой ключ от
`config:reload()`: `TT_LOG_LEVEL=debug` переживает reload с `level: error`.
Поэтому для кластера `TT_LOG_*` держат закомментированными, а уровень
меняют в конфигурации. `TT_LOG_FORMAT_DEFAULT`, наоборот, проигрывает файлу.
`TT_LOG_TO` и `TT_LOG_FILE` действуют только под `--config`, как и
подстановка `{{ instance_name }}` в пути; без `--config` ни они, ни
подстановка ничего не делают.

```yaml
log:
  format: json
  level: info
  modules:
    tnt.pool: debug
    tnt.http: error
```

Ни фасад, ни пакеты, ни приложение не зовут `log.cfg`, `log.level`,
`log.log_format`: `config:reload()` сотрёт заданное кодом, а `log.cfg{modules}`
заменит карту оператора целиком. Исключение допустимо у одного хозяина —
ядра приложения, которое ведёт свои настройки: оно отдаёт раздел `log`
своих настроек `log.cfg` на каждом применении конфигурации (перечитывание
её не стирает), только заданные поля, а карту модулей дополняет, а не
заменяет.

Фасад **только читает** уровень — ради ранней отбраковки: отброшенный вызов
стоит ~0,2 мкс вместо ~1,7 на сборку записи. Окончательно фильтрует ядро.
Уровень читается из `log.cfg` на каждой записи, и настройка, применённая
на ходу, действует со следующей записи.

Карта модулей плоская: `tnt: debug` на `tnt.pool` не действует, модуль вне
карты получает глобальный уровень. Имена модулей пишутся полностью — так,
как они переданы в `new`/`changes`: `tnt.pool`, `tnt.failover`, `app.http`.
Слой, принимающий имя журнала настройкой (метка слоя конвейера), пишет под
этим именем, и уровень ему задаётся тем же именем.

Настройка по разделу `log` на ходу меняет `level`, `modules` и `format`;
`to`, `file` и `nonblock` меняются только перезапуском. Без всякой настройки
действует `info` ядра.

**Запросы HTTP мимо фасада.** Сервер `http.server` пишет о запросах
встроенным журналом как есть, с тайнами, и пишет три разные записи:

| Что | Модуль и уровень |
|---|---|
| строка запроса `GET /customers/1?token=…` | `roles.httpd` на уровне из `log_requests`, если он задан роли; `http.server` на `info`, если не задан; `http.server` на `debug` у своего сервера с `log_requests = false` |
| весь запрос со всеми заголовками, `Authorization` тоже | `http.server` на `debug` |
| весь запрос с заголовками, если обработчик бросил | `http.server` на `error`; `roles.httpd` уровень не задаёт |

Выключить строку запроса роль не даёт, можно только опустить уровень,
поэтому в конфигурации роли ставится `log_requests: debug`, а раздел
`log.modules` держит `roles.httpd` и `http.server` на `info`. Нужны оба:
проверено запуском узла по конфигурации с `level: debug` —
`{ roles.httpd: info }` оставляет в журнале заголовки,
`{ http.server: info }` оставляет строку запроса. Своему серверу
с `log_requests = false` хватает `http.server: info`.

Чтобы бросок обработчика не дошёл до записи `http.server` с заголовками,
обработчики не выпускают исключений наружу: бросок становится отказом,
о нём пишет фасадом страж приложения — с опознавателем и причиной без
тайн, — а клиенту уходит 500 без текста броска. О самих запросах пишет
слой конвейера через фасад: метод, путь, поля строки запроса с вырезанными
тайнами, опознаватель запроса, код ответа и длительность по монотонным
часам.

## Чем пришлось поступиться

- **Настроек у пакета нет — ни `configure`, ни `default`, ни `status`.**
  У настройки журнала один хозяин: встроенный журнал и раздел `log`
  конфигурации кластера. Второй источник настроек в фасаде дал бы свои
  переменные уровня, вида и файла, которые `config:reload()` всё равно
  перезаписал бы заданным в конфигурации. Фасад только читает уровень —
  ради ранней отбраковки, — а окончательно фильтрует ядро.
- **Место вызова.** Ядро берёт `file`/`line` из третьего кадра стека. Внутри
  фасада все вызовы до ядра хвостовые, поэтому место — строка вызывающего.
  Но `pcall(logger.info, …)` у вызывающего даёт `[C]` и `-1`; `file` — это
  `short_src`, усечённый до 60 байт. По той же причине запись из слоя
  конвейера ставится вне `pcall`, а не внутри него.
- **Тайны** — только по имени и образцам (см. выше): чёрный список,
  а не белый.
- **Методов четыре** — `debug`, `info`, `warn`, `error`. `verbose` ядра
  у фасада нет: между «сведения» и «отладка» прикладному коду различать
  нечего.
- **syslog** дописывает заголовок и портит кириллицу побайтно.
- **`nonblock`** допустим только для pipe и syslog и при медленном читателе
  теряет записи; без него медленный читатель стопорит процесс.
- **`log.rotate()`** асинхронный.
- **Бортовой самописец EE** может ждать записей ниже уровня журнала, а ранняя
  отбраковка фасада их срежет. Цель пакета — CE.
- **`changes` считает только записи, прошедшие уровень**: запись,
  отсечённая уровнем, серию не рвёт и в счёт не идёт — иначе следующая
  запись получала бы счётчик неизвестно о чём. Поля контекста в отпечаток записи не входят —
  наравне с `instance_name`: одна и та же беда в двух запросах даёт разные
  `request_id`, и подавление повторов иначе не работало бы вовсе. Запись,
  прервавшая серию, несёт свой контекст, а не контекст первой записи серии.
- **`instance_name`** отсутствует до `box.cfg`: записи, сделанные
  до настройки узла — скажем, источником конфигурации, — идут без имени
  инстанса.
- **Свой кодировщик JSON для замера и для plain**, а не общий `json`:
  общий настраивает приложение (точность чисел, глубина), а ядро кодирует
  запись своим, с умолчаниями, и размер, измеренный общим, разошёлся бы
  с тем, что ляжет в буфер.

## Цена

Двойник ядра, вид json, 1e5 записей `{ endpoint, attempt, password, peers,
reason }` и 1e5 отброшенных `debug`; медиана прогонов, варианты чередуются
внутри прогона, машина занята соседними прогонами. Мкс на запись:

| Режим | `new` json | `new` plain | `changes` json | отброшенный `new` |
|---|---|---|---|---|
| интерпретатор | 10,47 | 9,52 | 13,51 | 0,20 |
| JIT | 8,90 | 7,06 | 11,52 | 0,13 |

Откуда цена (мкс на запись, интерпретатор / JIT):

| Часть | Мкс |
|---|---|
| фасад без ядра, json | 3,3–3,6 / 1,9–2,2 |
| ядро, plain, готовая строка | 2,8 / 2,4 |
| ядро, json, готовая строка | 5,5 / 5,2 |
| ядро, json, таблица записи | 6,6 / 6,4 |

Дорог вид json самого ядра: ~2,7 мкс сверх plain даже на готовой строке,
а таблицу ядро ещё копирует и кодирует (ещё ~1,1 мкс). В plain фасад дороже
на `render`, но ядро дешевле на столько же. `changes` дороже на тот же
`render`: отпечаток записи — её тело в plain.

Тайны: образцы гоняются только по строке, где есть двоеточие или `=`
и подсказка тайны, но ключи проверяются так же, как значения, и это
~0,45 мкс на пяти ключах. Подсказка в строке сверяется без памяти,
и адрес `http://127.0.0.1:2379` в каждой записи заново переводится
в нижний регистр — ещё 0,15–0,4 мкс; память на строках держала бы сами
строки (тысяча значений по 8 КБ — 8 МБ) и вытесняла бы из себя имена ключей.

Заполнители: запись без `{` стала дороже на 2 % в интерпретаторе
и на 5 % под JIT — только предпроверка. Запись с двумя заполнителями —
4,7 и 2,9 мкс: `gsub` с функцией замены на два имени. Порядок сборки
выбран под JIT: текст проходит окно и тайны до обхода полей, заполнители
и потолок — после. Обход полей — цикл `pairs`, который LuaJIT
не компилирует, и запись, начинавшаяся с него, стоила под JIT на 0,3 мкс
дороже: трассы рвались на входе, и строковая работа над сообщением шла
в интерпретаторе.

## Проверки

Проверки лежат в `test/` и идут на luatest: `.rocks/bin/luatest test/`.

- `log_test.lua` — в процессе проверок, на двойнике фабрики журналов ядра
  через `_set_source`: двойник получает ровно тот аргумент, который ушёл
  бы в ядро, и проверяется именно он — с разными уровнем, видом и именем
  инстанса. Тайны во всех местах, где они встречаются в жизни; значения,
  на которых ядро ломается; потолки строки и записи с точной границей;
  заполнители; поля контекста из настоящей области `context.run` и подменой
  средства `context`; подавление повторов; цена образцов на 8 КБ
  злонамеренной строки — не больше вчетверо против той же длины
  короткими строками, мегабайт — против окна.
- `builtin_test.lua` — настоящий журнал ядра в дочернем процессе: в процессе
  проверок его уже настроил luatest, и перенастроить нельзя. Сценарий
  настраивает журнал в файл своего каталога, пишет и выходит, а проверка
  читает файл: json и plain, `box.cfg` с именем инстанса, уровни
  по модулям против ранней отбраковки фасада (60 сочетаний), место вызова
  в горячем цикле с JIT и без, записи, на которых голое ядро ломается, —
  каждая строка файла разбирается строгим JSON, и тайны в файле ищутся
  дословно.

В своих проверках журнал ловят той же подменой: `_set_source({ logger =
двойник })` ставит фабрику журналов, `settings` — уровень и вид,
`instance_name` — имя инстанса, `context` — поля контекста (функция отдаёт
таблицу полей или `nil`); `_set_source(nil)` возвращает ядро. Журнал,
заведённый до подмены, пишет в двойник: фасад берёт средства на каждой
записи, а не при сборке. Проверка, загрузившая `tnt.log` из исходников,
возвращает прежний `package.loaded['tnt.log']` на место, а не выгружает
его: соседи, взятые раньше, держат ссылку на прежний экземпляр.

```lua
local written = {}

log._set_source({
    logger = function(name)
        return {
            info = function(argument)
                table.insert(written, { module = name, argument = argument })
            end,
        }
    end,
    settings = function()
        return { level = 'debug', format = 'json' }
    end,
})

log.new('tnt.pool').info('м', { password = 'hunter2' })
-- written[1] = { module = 'tnt.pool', argument = { message = 'м', fields = { password = '[скрыто]' } } }

log._set_source(nil)
```
