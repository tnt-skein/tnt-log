# tnt-log

Фасад над встроенным журналом Tarantool: записи уходят в `log.new(имя
модуля)`, вид json или plain и уровни по модулям остаются у ядра, а фасад
прячет тайны до передачи ядру, обезвреживает значения, на которых ядро
бросает или портит запись, держит потолок записи ниже буфера ядра,
подставляет поля в сообщение по имени и подавляет подряд идущие повторы.

```lua
local log = require('tnt.log')

local pool = log.new('tnt.pool')

pool.warn('соединение {endpoint} не открылось, попытка {attempt}', { endpoint = uri, attempt = 3 })
-- message: "соединение postgres://root:[скрыто]@db не открылось, попытка 3"
-- fields:  { endpoint = "postgres://root:[скрыто]@db", attempt = 3 }
```

```
{"time": "2026-09-13T11:22:25.213+0300", "level": "WARN", "message":"соединение postgres://root:[скрыто]@db не открылось, попытка 3","fields":{"endpoint":"postgres://root:[скрыто]@db","attempt":3}, "pid": 11838 , "cord_name": "main", "fiber_id": 104, "fiber_name": "app.lua", "file": "app.lua", "line": 15, "module": "tnt.pool"}
```

Зависит от `tnt-context` (поля контекста файбера в каждой записи)
и `tnt-external` (подмена журнала ядра в проверках).

## Зачем

Писать записи, держать файл, переоткрывать его по SIGHUP, фильтровать
по уровню и печатать JSON умеет само ядро. Не умеет оно другого, и каждый
пункт стоит дорого, если забыть:

- **Тайны.** Пароль из поля и из `log.info('%s', tbl)` ядро печатает как
  есть. Фасад прячет их по имени поля (`password`, `token`, `api_key`,
  `authorization`…) и по образцам в строках — адрес с паролем, пара
  `token=…`, заголовок `Authorization: …` — до передачи ядру, на любой
  глубине, в сообщении и в ключах.
- **Значения, на которых ядро ломается.** `nan` и `inf` уходят литералами,
  int64 теряет цифры у разборщика на double, невалидный UTF-8 проходит
  сырыми байтами, кольцо и 129-я вложенная таблица бросают в вызывающего,
  ключ-boolean тоже. Фасад пишет `"nan"`, десятичную строку, `[не UTF-8,
  N байт]`, `[кольцо]`, `[глубже]` и ключ строкой.
- **Потолок записи.** Запись длиннее ~16 КБ ядро режет с битым JSON,
  а в plain склеивает со следующей. Фасад держит строку в 4096 байт
  и запись в 15000, а не влезшую заменяет запасной с `truncated = true`.
- **Ничего не теряется.** `log.info('%s %d', 'a', 1)` у ядра выбрасывает
  `1`, а поля вызывающего с именами полей ядра — `file`, `level`, `pid`
  и ещё пять — выбрасывает молча. У фасада всё переданное лежит внутри
  `fields`, лишние аргументы — в `args`.
- **Контекст запроса.** Опознаватели запроса и трассы из `tnt-context`
  ложатся верхними полями, прочие ключи — объектом `context`: запись
  находится по запросу, из которого её написали.
- **Повторы.** `log.changes(имя)` пишет первую запись серии, а к записи,
  которая наконец изменилась, добавляет `suppressed` — сколько раз
  повторилась прежняя.

Метод журнала никогда не бросает: запись о беде не должна становиться
второй бедой. Настроек у пакета нет: уровень, вид и назначение — у ядра
и раздела `log` конфигурации кластера, фасад только читает уровень ради
ранней отбраковки.

## Установка

```sh
tt rocks install tnt-log --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-log.git
cd tnt-log && tt rocks make
```

## Как пользоваться

```lua
local log = require('tnt.log')

local pool = log.new('tnt.pool')          -- журнал модуля: debug, info, warn, error
local agent = log.changes('tnt.failover') -- то же, но подряд идущие повторы подавляются

pool.info('пул готов')
pool.warn('соединение не открылось', { endpoint = uri, attempt = 3, password = 'hunter2' })
pool.info('%s %d', 'a', 1)               -- fields = { value = 'a' }, args = { 1 }

agent.info('назначение прочитано', { leader = 'storage-001-a' })
agent.info('назначение прочитано', { leader = 'storage-001-a' })   -- подавлена
agent.info('назначение сменилось', { leader = 'storage-001-b' })   -- suppressed = 1
```

| Вызов | Что делает |
|---|---|
| `new(name)` | журнал модуля с методами `debug`, `info`, `warn`, `error`; имя — до 128 байт из латиницы, цифр, точки, подчёркивания и дефиса, негодное бросает |
| `changes(name)` | тот же журнал, но подряд идущие повторы не пишутся, а прервавшая серию запись несёт `suppressed` |
| `метод(msg, fields, ...)` | `msg` — строка с заполнителями `{имя}`; `fields` — таблица; всё после — в `args` |
| `secret_hints`, `secret(name)`, `scrub(text)` | список подсказок тайн, проверка имени, строка со спрятанными тайнами |
| `is_name(name)`, `NAME_RULE` | годится ли значение в имя журнала и правило словами |
| `render(record)` | тело записи в виде plain |
| `HIDDEN`, `CYCLE` | `[скрыто]` и `[кольцо]` |
| `_set_source(подмена)` | журнал ядра, его настройка, имя инстанса и поля контекста — для проверок |

Запись в json — `message`, `fields`, `args`, `instance_name`, поля
контекста, `suppressed`, `truncated` — внутри записи ядра с его `time`,
`level`, `module`, `file`, `line`. В plain — одна строка: сообщение, пары
фасада, пары вызывающего по алфавиту, поля контекста.

Уровень решает ядро — раздел `log` конфигурации кластера или
`box.cfg{ log_level, log_modules }`; карта модулей плоская, имя журнала
в ней пишется полностью.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и tnt-context, tnt-external в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Фасад проверяется на двойнике фабрики журналов ядра — двойник получает
ровно тот аргумент, что ушёл бы в ядро, — а настоящий журнал ядра
в дочернем процессе: json и plain, `box.cfg` с именем инстанса, уровни
по модулям, место вызова в горячем цикле, записи, на которых голое ядро
ломается. Покрытие строк — 100 %, убитых мутантов — 100 %.
